## 维护方法

1. 只改 `config/characters.json` 中对应角色。姓名、性别、年龄、性格、背景、爱好、说话方式、voiceId、图片位置都在同一条记录中。角色 ID 保持稳定，修改档案后递增 version。
2. 场景单独维护在 `config/scenes.json`，通过 characterId 引用角色、displayOrder 决定首页排序。新增场景可以复用同一人物，不复制人设。图片沿用 3×2 图集规则；更换图集需同时放入网页和小程序的 assets 目录。
3. 执行 `npm run sync:catalog`，生成网页、小程序的目录与本文件；执行 `npm test`，然后重新启动后端、刷新网页或重新编译小程序。`npm start` 也会自动同步。
4. 更换声音时，先在 voices 中登记当前模型支持的准确 ID、声音性别、语言和官方来源，再改人物的 voiceId。旧的 .env QWEN_VOICE 已不参与角色选择，避免把所有人覆盖成同一声音。
5. 开始新会话时，服务端根据场景选择人物并锁定音色。通话中切换沉浸/语音球画面不会换人或重连；换人物需要结束当前通话再进入另一个场景。

程序启动时校验重复 ID、断开的场景引用、性别与音色对应及图片映射；错误会明确失败，不静默退回统一女声。session.ready 返回角色 ID、名字、档案版本和 voice ID 的快照，便于未来扩展历史记录。当前不新增跨会话记忆、聊天记录存储、声音克隆或后台管理系统。
