真正实时对话，先把你自己陪练好。

已确认：名字为“AI口语搭子”；服务有基础但不敢开口的成年人；直接做实时语音；前期主要自己使用，调好后再发布。本版重新编写，未调用产品设计 skill，也未沿用上一版一问一答方案。

推荐决策：首选测试“原生实时语音模型 + 自有轻量后端 + 微信小程序”。候选模型为北京地域 qwen3.8-omni-flash-realtime。一个 Agent 的角色、教学规则与会话状态可以由我们自己的代码管理，扣子不是前置条件。若需要可视化配置和现成 SDK，备选扣子在线版 WebSocket；当前不投入本地部署扣子。

1. 三种实现方式怎么选

方式适合什么情况代价与判断
模型 API + 轻量后端由代码管理提示词、实时会话、字幕、学习记录和用量按量试用，控制直接；需要自己接音频采集、播放与打断。作为本项目首选技术验证。
扣子在线版 + WebSocket希望在网页后台编辑 Agent、提示词、变量，并使用官方语音 SDK确有双向音频与打断；语音识别、合成、文字模型和套餐共同影响费用。保留为备选。
本地 Coze Studio确实需要自托管 Agent 平台和工作流基础设施自托管的是编排平台，不等于本地运行语音模型。未核实云端实时语音服务可等价自部署；现阶段收益不足以覆盖维护工作。

扣子云端官方确认 WebSocket 和 RTC 均支持双向流式语音、语音打断和字幕；WebSocket 不额外收 RTC 通话费。开源 Coze Studio 的功能不能直接等同云端扣子，Coze Loop 则主要用于提示词、评测和观测。依据：扣子接入对比、Coze Studio、Coze Loop。

2. Agent 和实时语音如何连接

微信小程序持续收音、流式播放、字幕、打断
⇄
我们的后端提示词、会话状态、连接、额度和用量
⇄
实时语音模型直接接收音频、输出音频与文字

实时会话建立后持续传送音频，不需要用户每句话点击发送，也不需要每一轮重新运行一条长工作流。实时模型支持通过 session.update 的 instructions 设置角色与行为。它可以成为“口语搭子”的核心推理能力；应用代码提供另外的控制层。依据：实时模型接入、会话配置与事件。

  1. 点击“开始对话”，客户端向自己的后端申请会话；后端检查登录、并发与预算，创建云端 WebSocket 连接。
  2. 后端填入系统提示词、场景、学习偏好和有限的学习记忆，配置英语音色、音频格式与说话结束检测；确认配置成功后开始收音。
  3. 小程序将录音帧持续发给后端，再转给模型；模型判断用户说完后，流式返回文字和声音。客户端连续播放，而不是等完整音频文件。
  4. 用户在 AI 讲话时开口：立即停止本地声音、清空播放队列、通知模型取消回答、丢弃旧回复的迟到音频。只停本地播放器是不够的。
  5. 每轮记录云端返回的实际用量和延迟；挂断时关闭录音、播放和双方连接，清理异常遗留会话。
  6. 结束后单独进行简短的文字总结，保存一个值得复练的表达。总结和统计不插入实时语音的关键路径。

打断后还要验证模型如何处理用户未听到的后半段内容。当前查阅的 Qwen 客户端文档没有确认 conversation.item.truncate；不能直接照搬其他厂商事件。必要时通过重建会话并带入已确认的对话摘要恢复一致性，需实测后定案。

3. 提示词约束与程序约束分开做

提示词负责行为引导程序负责明确执行
简单英语、稍慢语速、通常每次1—2句、一次问一个问题音频格式、播放队列、取消生成、超时、连接恢复
先回应意思；只改一个点；需要时简短中文帮助；给用户主动提问机会密钥保管、模型白名单、单用户并发、会话时长与预算阈值
没听清时确认；区分语法错误与更自然的表达；不捏造精确发音分数实际usage记录、保存/删除学习记录、结构化总结校验

起始配置建议：单用户同时一通；每次建议10分钟；长期空闲自动结束；预算先设每日3元、每月50元作为测试阈值建议，不是报价、扣款授权或可保证绝不超出的账单上限。已生成但未收到用量的内容可能继续产生结算，应保留余量并核对账单。

说话结束检测先测试 semantic_vad，将停顿阈值在1.2—1.8秒附近调试，照顾学习者组织语言的停顿。这个取值是待验证的初值。代码同时保留显式停止/挂断。max_tokens 的官方语义是截断返回，不影响生成过程，不能把它当作费用硬上限。

提示词草稿的核心内容
你是AI口语搭子，帮助有基础但不敢开口的成年人练口语。

一次最多问一个问题，留出用户表达和主动提问的空间。

4. 微信小程序先做音频验证

微信官方类型定义已有 PCM 录音、分帧回调、WebAudio 音频缓冲与定时播放能力，因此可以验证“录音帧 → 后端 WebSocket → 实时模型 → PCM 播放队列”。frameSize 单位是 KB；InnerAudioContext 不能直接当成连续 PCM 播放器。接口存在不代表同录同播、外放回声和自然打断已经可靠。依据：微信官方 API 类型定义。

第一项开发产物应是一页真机音频验证界面：开始、挂断、字幕、费用记录。先测耳机，再测外放，并检查录音十分钟边界、切后台、电话中断和蓝牙切换。用真实观测确定第一声延迟与打断效果。

TRTC 另一条路线涉及企业主体、指定类目及 live-pusher/live-player 权限，个人自用不会自动豁免。它不等于普通录音 API 的限制。若没有可用 AppID 或小程序音频仍不稳定，可先用 H5 临时验证模型，最终平台仍保留为微信小程序。H5 成功不能替代小程序验收。依据：TRTC 小程序接入条件。

5. 直连实时模型的费用

本次2026-10-01访问到的 qwen3.8-omni-flash-realtime 北京原价：每百万 token，音频输入6元、音频输出12元、文本输入1.5元、文本输出4.5元。输出语音与对应文字分别计费。依据：官方模型定价。

一场10分钟练习，假设用户说4分钟、AI说3分钟。只计算新增音频会得到约0.037元，但这不是整场费用：多轮会重复计入历史音频和文字，系统提示词也参与输入。下表改用整场累计计费的用量做敏感性计算，避免漏算历史。

6. 如果用扣子，选在线版 WebSocket

实际步骤：在扣子创建陪练 Agent → 配置提示词和变量 → 发布为 API → 后端管理调用凭证 → 通过 wss://ws.coze.cn/v1/chat?bot_id=… 建立双向音频会话 → 在 chat.update 中传 level、scene 等变量并配置语音检测。

自由对话需显式设置 server_vad，不要沿用默认按键模式；停顿阈值需要调试。文档中的语义判停和部分高级降噪属于企业旗舰能力，个人方案不能默认拥有。官方提供 UniApp SDK 和微信小程序示例，但仍需真机验证。依据：扣子会话事件、双向对话接口、官方UniApp SDK。

按大模型流式识别75积分/分钟、TTS 2.0系统音色0.3积分/字符测算，10分钟练习、识别计量4—10分钟、输出2,000英文字符，会消耗约900—1,350积分/次，再加文字模型。识别服务不会只按净说话时间计量；打断时已合成内容也可能收费。30次音频为2.7—4.05万积分。现金价等值约0.9—1.35元/次，不代表个人账户可以直接按次付现金。依据：扣子音视频计费。

本次查到的个人进阶版刊例为39.9元/月、3万积分，高阶版99元/月、9.9万积分；实际购买、可用积分和权益以账户页面为准。套餐支出不能再机械叠加一遍已由所含积分抵扣的消耗。依据：扣子套餐、积分规则。

7. 先验证什么，再做产品

  1. 真机音频：持续收音、连续播放、打断、挂断后停止计费连接。小程序探针优先于完整页面开发。
  2. 对话质量：你说得慢时会不会抢话、英文是否适合你、中文求助后能否回到练习、纠错是否准确且适量。
  3. 真实费用：完成几场10分钟练习，对比usage与云账单，记录转写、总结和失败重试的额外消耗。
  4. 学习体验：再接入保存表达、练后复盘和少量学习记忆；你持续用起来以后，再考虑发布、多人账户和收费。

本次完成的是官方资料核验、实现方案和提示词草稿。没有安装扣子、调用付费API或验证真实手机通话。模型接入权限、英音质量和账单仍需实际账户与设备验证。
